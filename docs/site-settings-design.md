# 站点设置设计

## 设计方向

管理后台采用与 cffk 一致的中性、工具型设置界面：白/灰基础色、清晰的分组边界、紧凑表单和可扫描的字段说明。CFPay 是单商户收款系统，不引入营销页、装饰性大图、渐变背景或无实际行为的配置。

本次站点设置的核心差异是“编辑即预览”：左侧编辑收银台公开信息，右侧同步展示一个真实收银台结构的静态预览；移动端自动改为单列，不产生横向溢出。

## 当前缺口

| 缺口 | 影响 | 处理 |
| --- | --- | --- |
| 没有站点图标和品牌图 | 浏览器标签页、收银台顶部无法识别商户 | 增加安全校验的内置图片上传，图标和 Logo 均存 D1 |
| 没有公开站点地址 | 收银台缺少 canonical / 分享来源信息 | 增加可选的 HTTP/HTTPS 地址，仅用于公开页面元数据 |
| 没有客服提示 | 付款失败、微信不可用或订单过期时缺少人工处理入口 | 增加收银台客服提示，支持多行纯文本，不执行 HTML |
| 没有修改后预览 | 管理员保存前无法确认长文案和图标的显示效果 | 增加安全的本地静态预览 |
| 文案分组不清晰 | 品牌信息、付款说明和页脚混在一起 | 拆成“品牌基础”“品牌资源”“收银台说明”“页脚与客服” |

## 有意不加入的功能

- 不加入 Logo 外链、媒体库、OSS 或任意 HTML/JavaScript 注入。当前系统不需要外部媒体存储，且这会扩大安全边界。
- 不加入注册开关、商城首页内容、商品 SEO、自定义代码等 CFFK 专属配置。CFPay 没有用户注册和商品首页，这些字段只会形成无效设置。
- 不增加可配置时区。当前业务约束为单商户、东八区，面板和订单时间口径已经固定为 `Asia/Shanghai`；新增一个不影响业务的时区字段会制造误导。

## 数据契约

`system_setting` 继续使用单行配置模型，新增字段均使用空字符串默认值，兼容已有 D1：

- `public_site_url`：可选的 HTTP/HTTPS 地址，最大 2,048 字符；禁止用户名、密码、查询串和片段。
- `logo_data_url`：可选的 PNG/JPEG/WebP/ICO data URL，最大 512 KB。
- `support_text`：可选纯文本，最大 1,000 字符；按原文换行展示。
- `favicon_data_url`：可选的 PNG/JPEG/WebP/ICO data URL，最大 512 KB。

服务端始终重新校验字段，缺失字段保留旧值，空字符串表示清除可选配置。图片不接受 SVG，避免把主动内容带入公开页面。

## 收银台使用规则

- Logo 有值时显示在站点名称左侧，无值时使用默认文字标识。
- Favicon 有值时写入 `<link rel="icon">`，否则回退 `/favicon.svg`。
- 站点地址只生成 canonical 和 Open Graph 的安全元数据，不参与订单回调或金额逻辑。
- 客服提示只以转义后的纯文本展示，支持换行，不解析链接、HTML 或脚本。
- 订单已支付、已过期或微信通道不可用时仍保留客服提示，帮助用户处理异常，但绝不恢复二维码和倒计时。

## 管理端品牌与版本检测

- 管理端侧栏顶部的 `reka-ui` 下拉菜单触发器使用站点名称、副标题和 Favicon，不再显示写死的钱包图标；站点设置保存成功后通过页面事件即时刷新，不要求重新加载后台。
- “检测更新”直接读取 构建时注入的更新清单地址 `VITE_UPDATE_MANIFEST_URL` 的版本号，不再请求只能反映当前部署版本的 `/api/health`。
- 根 `package.json`、Worker `APP_VERSION`、管理端构建版本和 Windows 监控端版本必须一致，测试与 Vite 构建都会检查版本漂移。
- GitHub 原始文件地址只适用于公开仓库。当前仓库若保持私有，该地址会返回 404，管理端显示“检查失败”；启用在线更新检测前必须公开仓库，或后续提供带鉴权的公开版本清单服务，不能把 GitHub 私人令牌下发到浏览器。

## 验收清单

- 桌面端编辑区和预览区不互相挤压，长地址和长文案可换行。
- 移动端所有内容在视口内，图片按固定尺寸约束，文件名和错误信息可换行。
- 图片格式、大小和 data URL 前缀由浏览器和 Worker 双重校验。
- 保存成功、读取失败、图片格式错误均有中文 Toast 或页面级错误提示。
- 修改后的站点名称、Logo、Favicon、公开地址、公告、客服提示和页脚在新收银台中生效。
- 空值清除后回退到内置图标和默认文案，不留下旧数据。
